# SER001 — retired

**This diagnostic is no longer produced.** Vector set support in current library versions is not marked
experimental, so nothing emits `SER001` and no suppression is needed. The page is kept because the
diagnostic's help link pointed here, and older builds still carry it.

If you have a suppression for `SER001` — in a `csproj`, a `.editorconfig`, or a `#pragma` — it is now
inert, and can be removed whenever it suits you.

## What it used to mean

At the time, [Redis documented that](https://redis.io/docs/latest/commands/vadd/):

> Vector set is a new data type that is currently in preview and may be subject to change.

The corresponding library feature therefore had to be considered subject to change too:

1. Existing bindings might cease working correctly if the underlying server API changed.
2. Changes to the server API might require changes to the library API, manifesting in either/both of
   build-time or run-time breaks.

Acknowledging that was what the suppression meant:

```xml
<NoWarn>$(NoWarn);SER001</NoWarn>
```

or more granularly / locally in C#:

``` c#
#pragma warning disable SER001
```

## Reserved, not recycled

`SER001` is not reused for anything else, so an old suppression cannot silently hide an unrelated
warning. The same applies to the other retired identifiers — see `Experiments.cs`.
