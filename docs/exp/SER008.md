# Redis 8.10 features — SER008 retired

**This diagnostic is no longer produced.** The Redis 8.10 bindings are no longer marked
`[Experimental]`, so nothing emits `SER008` and no suppression is needed. The page is kept because the
diagnostic's help link pointed here, and older builds still carry it.

If you have a suppression for `SER008` — in a `csproj`, a `.editorconfig`, or a `#pragma` — it is now
inert, and can be removed whenever it suits you.

## What it covered

New features in Redis 8.10:

- Session-based bulk hash import via fieldsets (`HIMPORT`), surfaced as `IDatabase.HashImport`/`HashImportAsync`

## What it used to mean

While Redis 8.10 was in preview, the corresponding library features had to be considered subject to change too:

1. Existing bindings might cease working correctly if the underlying server API changed.
2. Changes to the server API might require changes to the library API, manifesting in either/both of
   build-time or run-time breaks.

Acknowledging that was what the suppression meant:

```xml
<NoWarn>$(NoWarn);SER008</NoWarn>
```

or more granularly / locally in C#:

``` c#
#pragma warning disable SER008
```

## Reserved, not recycled

`SER008` is not reused for anything else, so an old suppression cannot silently hide an unrelated
warning. The same applies to the other retired identifiers — see `Experiments.cs`.
