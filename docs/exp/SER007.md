# Client-side geographic failover — SER007 retired

**This diagnostic is no longer produced.** Client-side geographic failover is no longer marked
`[Experimental]`, so nothing emits `SER007` and no suppression is needed. The page is kept because the
diagnostic's help link pointed here, and older builds still carry it.

If you have a suppression for `SER007` — in a `csproj`, a `.editorconfig`, or a `#pragma` — it is now
inert, and can be removed whenever it suits you. This is the removal the previous version of this page
said to expect: *"the diagnostic simply stops being emitted, with no code change needed on your side."*

## The feature

This feature is used to fail over between multiple redundant endpoints that can each serve your workload - designed for an
**Active-Active** (geo-distributed, bidirectionally-replicated) deployment, but usable over any set of endpoints, including ones
with no replication between them (see the full docs for what that means for your data). It is functionally similar to the
"multi-DB client" concept in other Redis clients (Jedis' `MultiDbClient`, redis-py's `MultiDBClient`); please see
[full docs](/Failover).

It was a shipped, supported feature throughout - not a preview, not gated on an unreleased server version,
and not dependent on any server API subject to change. What the marker reserved was the right to adjust
*this library's* API surface without the usual backwards-compatibility guarantees, because it was a large,
brand-new public API arriving in a single release and a surface that size is hard to correct once locked down.

That exposure has now happened, so the surface is covered by the usual compatibility guarantees like any other.

## What it used to mean

Suppressing the diagnostic was the normal way to use the feature, and acknowledged the above:

```xml
<NoWarn>$(NoWarn);SER007</NoWarn>
```

or more granularly / locally in C#:

``` c#
#pragma warning disable SER007
```

## Reserved, not recycled

`SER007` is not reused for anything else, so an old suppression cannot silently hide an unrelated
warning. The same applies to the other retired identifiers — see `Experiments.cs`.
