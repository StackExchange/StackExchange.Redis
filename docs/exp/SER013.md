SER013 - retired
-

**This experiment is over, and the answer was yes.** The interpolated-string RESP writer - `RespContext`,
`RespRequestBuilder`, `RespRequestFrame`, `RespFragment` - and the command groups built on them
(`db.Strings`, `db.Hashes`, `db.Keys`, ...) are **normal, supported API from 4.0**. Nothing is gated, and
there is nothing to opt in to: delete any `SER013` suppression you added, and the code keeps working.

See [Basic Usage](../Basics) for how the surface reads, [The original `IDatabase` API](../LegacyApi) for
what the previous spelling maps to, and [Extending the client](../Extending) if you are adding commands of
your own.

The ID stays reserved and is never reused, so an old `<NoWarn>SER013</NoWarn>` in somebody's project file
remains harmless and this page remains findable.

> **Renumbered from SER010.** While this was in development, 3.x independently shipped `SER010` as
> *maintenance notifications* — a different feature entirely, and a released one, so it keeps the number.
> Nothing ever shipped emitting `SER010` for the writer, so no released build is affected. If you built
> against a pre-release of this branch and carry `<NoWarn>SER010</NoWarn>` for *this* reason, drop it: it
> now suppresses [maintenance notifications](SER010) instead, which is almost certainly not what you want.

Design notes - what was measured, what was only reasoned about, and the decisions that were taken and
rejected along the way - are in `design/interpolated-resp-writer.md`.
