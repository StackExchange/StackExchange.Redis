SER012
-

Borrowed reply values: `RespValue`, `IRespBufferOwner`, and every command that hands back a
`ReadOnlyLease<RespValue>`.

A `RespValue` is a window onto a buffer somebody else owns - normally the lease it arrived in. That is
what makes a multi-value reply nearly free: one pooled array of windows over one reply buffer, where a
lease of `RedisValue` is one pooled array **plus an allocation per element** that is neither small nor a
canonical number. Measured at 77x less garbage for a thousand 32-byte values.

It also means the values are only valid until the owner is disposed. Reading one afterwards throws
`ObjectDisposedException` rather than returning recycled bytes, but it still throws - so a value that has
to outlive the lease must be copied out first, with `AsRedisValue()`, `(string?)` or `CopyTo`.

**This ID is separate from SER010 on purpose.** The interpolated writer is one question ("should commands
be written this way?"); this is another ("should replies be borrowed rather than owned?"), and they can
be answered differently. Turning this one off tells you how much of your code depends on the borrowing.

Settled enough to build on:

- the window-plus-owner shape, and that the owner rather than a `ReadOnlyMemory<byte>` is what preserves
  the disposal check
- scalar-only, enforced at capture, so the accessors are total
- delegation to `RespReader` for every accessor, so there is no second copy of the parse rules, the
  coercions, or the streamed-chunk walk
- the lease owning both its array and the reply buffer, releasing both on dispose

Not settled, and the reason this is gated:

- **Equality is payload bytes.** `:1` and `$1\r\n1` are equal because their payloads are the same digit;
  `,1.0` and `:1` are not, where `RedisValue` would coerce. That is the honest rule for a wire-level type
  and a real behaviour difference from what it replaces.
- **`GetHashCode` on a streamed value returns its length**, which is correct but coarse.
- **Singular reads still return `RedisValue`.** `Get(key)` is allocation-free already for small values and
  needs no `using`; the large-single-value case is served by `GetLease`. Whether that split is right, or
  whether consistency should win, is open.
- **Aggregates are not covered.** `RespValue` is scalar-only, so a nested reply - streams, `VLINKS` -
  still materialises. The type these become is the next question, not this one.

To opt in, add `SER012` to `NoWarn`, or suppress it at the call site.
