# SER351: `[Resp]` declaration cannot be implemented

The `[Resp]` generator implements declarations of these two shapes:

```c#
[Resp] private static partial RespFragment Nx { get; }                 // a token, pre-framed
[Resp("CMS.INFO")] private static partial RespCommand CmsInfo { get; }  // a command name, resolved once
```

Anything else carrying `[Resp]` is skipped. This rule exists so that skipping is *said* rather than silent -
without it, the only symptom is `CS9248: partial property must have an implementation part` on a declaration
that looks perfectly correct, with nothing anywhere explaining why nothing was generated.

## Causes

**The property is not of type `RespFragment` or `RespCommand`.** There is nothing meaningful to emit for
another type.

```c#
[Resp] private static partial int Nx { get; }   // SER351
```

**The property is not `partial`.** There is no implementation part for the generator to supply, so the
attribute does nothing at all.

```c#
[Resp] private static RespFragment Nx => default;   // SER351
```

**A `RespCommand` was given more than one token.** A command is one name; what follows it is an operand.

```c#
[Resp("CLIENT", "KILL")] private static partial RespCommand ClientKill { get; }   // SER351
```

Declare the command, and the subcommand as a fragment: `[Resp("CLIENT")] ... RespCommand Client` and
`[Resp("KILL")] ... RespFragment Kill`.

**A `RespCommand` name is not printable ASCII, or contains whitespace.** A space, CR or LF in a command name would
desynchronise the connection, so it is refused when you build - the same check `.Command()` makes at run time.

```c#
[Resp("CMS INFO")] private static partial RespCommand CmsInfo { get; }   // SER351
```

## Fixing it

Make the declaration `partial` and of type `RespFragment`, or remove the attribute if it was not meant to be
generated. If you need a fragment built at runtime rather than from declared tokens, use
`RespFragment.CreateValidated`, which checks the framing instead.
